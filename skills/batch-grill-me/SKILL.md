# 批量澄清

持续深入访谈用户，直到双方达成共同理解。将方案梳理为一棵决策树：每个决策都会分出依赖它的后续决策。

按轮次推进这棵树。当前可提问的范围，是所有前置条件已经确定的决策——这些问题可以现在提出，无需猜测尚未听到的答案。每轮提出这一范围内的全部问题，为每个问题编号并给出推荐答案。然后等待用户回答，再开始下一轮。

用户每轮的回答都会重塑决策树：已确定的决策向外推进可提问的范围，解锁依赖它们的问题。重新梳理这一范围，再提出下一轮问题。如果一个问题的答案依赖本轮另一个尚未回答的问题，就把它留到后续轮次。

调查事实是你的工作，不是用户的工作。如果当前问题需要环境中的事实，例如文件系统或工具信息，派子 Agent 调查，不要把自己能查到的事情交给用户。不要因此阻塞整轮访谈：正在进行的调查属于尚未满足的前置条件，只有依赖它的问题需要等待；其余问题现在就问。决策由用户做出——逐项交给用户，并等待回答。

当没有剩余可提问的问题，且决策树的每个分支都已探讨、没有未解决的前置条件或被默默假定的决策时，访谈才算结束。在用户确认双方已达成共同理解之前，不要执行方案。

## 提问方式（本地补充）

- 当前环境提供且允许调用结构化提问工具时，优先使用该工具，例如 Cursor 的 `Ask Question`、Codex 的 `request_user_input` 或同类工具。以当前实际可用工具及其调用规则为准，不假定工具名称或能力始终相同。
- 将同轮互不依赖的问题尽量放在一次调用中。超过工具允许的问题数量时拆成多批，保留问题编号；拆批不改变决策依赖，不能提前提出依赖未回答问题的后续问题。
- 适合选择题时，提供清晰且有意义的选项，并标明推荐答案及简短理由。开放问题保留自由回答空间，不为凑选项强行限制答案。
- 工具不可用或当前模式不允许调用时，回退到编号文本问题，仍提供推荐答案，并等待用户回复。
- 使用异步提问工具时，调用返回不代表用户已回答。等待实际答复后，才能确定相关决策或推进依赖它的分支；等待期间可以继续独立的事实调查。

## 环境兼容（本地补充）

没有可用子 Agent 时，自行使用现有工具调查事实。无法查证的信息明确说明，再向用户询问必要信息，不编造调查结果。
